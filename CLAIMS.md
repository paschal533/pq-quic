## Method notes

- The decoder's key derivation is checked against RFC 9001 Appendix A.1 (`--self-test`).
- Datagram counts include ACK-only Initials (padded), so `initial_datagrams` is not "datagrams carrying the ClientHello". Do not quote it as such.
- Listener stdout must be drained. Before commit after 15ae4ec, `bench_handshake.py` stopped reading the listener after its `peer` line. On Windows the pipe holds 4 KiB (~66 `accepted` lines), after which the listener blocks and every later dial times out. Runs with ≤ 61 dials (pilot, targeted: C-17–C-19) were under the limit and report zero failures. The first random-loss run (randomloss-20261026T193754Z, 167/200 pairs failed from pair 33) is discarded. The bench now prints `listener accepted=N` to check.
- Trace markers: `trace_hs_ms` = first delivered client Handshake packet, which can be a bare ACK sent before the whole server flight has arrived, so it misses server-flight loss. C-18/C-19 use it. For drop-#1 hybrid, the 1-RTT marker agrees (rust median 148 vs 147 ms). `trace_complete_ms` (first sent client 1-RTT packet) is not a reliable completion marker for rust-libp2p, which can return from dial before sending 1-RTT. Use dialer `elapsed_ms` until Handshake-space decryption exists.
- netem and GSO: on Linux, quinn sends the two 1,200-B halves of a hybrid hello as one 2,400-B GSO batch, which netem on `lo` keeps or drops as a unit (seen on the wire with an AF_PACKET sniff). quic-go did not batch handshake datagrams. `tc -s` counts GSO segments, so it does not show this. Run netem with `PQQUIC_DISABLE_GSO=1` and `QUIC_GO_DISABLE_GSO=true`. The GSO-on rust run `netem-20261027T161737Z` is invalid for C-30 and kept only as a record.
- The Windows tap runs are not affected by send batching. quinn-udp also batches on Windows (`UDP_SEND_MSG_SIZE`, quinn-udp 0.5.x `src/windows.rs:394`), but the tap's socket receives single datagrams: across the nine rust tap traces behind C-22..C-26 (≈103,000 datagrams) the largest is 1,452 B and none exceeds it.
- Tap cost per client: `quic_tap.py` keeps one back socket per client address and never closes it (≈401 per cell; Windows `select()` limit 512). At 25 ms delay there is no drift in connect time across a cell (go, no loss: first-quarter median 131.0 ms, last-quarter 132.8 ms), but with 0 ms delay both variants drift from 12 to 31 ms (`pilot-20261026T172756Z/go-d0-l0.csv`). Do not use the tap for LAN-profile timing; use netem.
- Listener connection lifetimes are bounded, not leaking: rust-pair swarm idle timeout 5 s with quinn idle timeout 10 s (vendored `config.rs`); go-libp2p uses quic-go `DefaultIdleTimeout` 30 s with keep-alive 15 s (go-libp2p v0.51.0 `p2p/transport/quicreuse/config.go:14`), and the go dialer closes gracefully. At most a few dozen connections are open at once.
